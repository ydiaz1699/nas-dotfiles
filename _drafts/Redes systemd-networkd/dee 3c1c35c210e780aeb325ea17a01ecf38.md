# 🔒 Guía segura: Debian + systemd-networkd + Docker Compose + AdGuard (macvlan)

## 📌 Requisitos previos

- Servidor Debian **recién instalado** (sin entorno gráfico, con SSH server y utilidades estándar).
- Acceso **físico** o a través de la consola del hipervisor (por si algo falla, puedas rescatar el sistema).
- Red local: rango `192.168.0.0/24`, router en `192.168.0.1`.
- Las IPs son ejemplos → **ajústalas** a tu red.

| Dispositivo | IP fija asignada |
| --- | --- |
| Servidor (eno1) | `192.168.0.200` |
| Host shim (macvlan-shim) | `192.168.0.250` |
| Contenedor AdGuard | `192.168.0.201` |
| Router / Gateway | `192.168.0.1` |

---

## 🛡️ Principios de seguridad para evitar perder red

1. **Nunca** desactives `networking` sin tener `systemd-networkd` **funcionando y con IP**.
2. **Siempre** añade `ConfigureWithoutCarrier=yes` en el archivo `.network` de la interfaz física.
3. **Primero** crea el shim macvlan del host, **después** configuras la IP fija.
4. **Antes de apagar** el sistema antiguo, programa un **respaldo automático** (con `at`) que reactive la red en caso de error.
5. **Verifica cada paso** antes de continuar.

## 📦 Parte 1 – Instalación base de Debian (si no la tienes)

Durante el instalador:

- Selecciona **"Debian GNU/Linux"** (sin entorno gráfico).
- En selección de software: solo ✅ `SSH server` + ✅ `standard system utilities`.
- Configura la red con **DHCP** (la fijamos después).
- Completa la instalación y haz el primer boot.

Conéctate por SSH (como `root` o con `sudo`) y actualiza:

```bash
apt update && apt upgrade -y
apt install -y at curl git ufw
```

## 🌐 Parte 2 – Migración segura a systemd-networkd

### 2.1 Identifica tu interfaz Ethernet real

```bash
ip link show | grep -v lo | grep -E "^[0-9]+:"
# Aparecerá algo como "eno1", "eth0", "ens18"
export IFACE="eno1"   # cámbialo si es diferente
echo $IFACE
```

### 2.2 Programa un “rescate” automático (5 minutos)

Si cometemos un error, la red se reiniciará sola con la configuración antigua.

```bash
echo "systemctl restart networking" | at now + 5 minutes
```

### 2.3 Crea la configuración de systemd-networkd **sin tocar servicios aún**

### Archivo `.network` para la interfaz física

```bash
cat > /etc/systemd/network/10-${IFACE}.network <<EOF
[Match]
Name=${IFACE}

[Network]
Address=192.168.0.200/24
Gateway=192.168.0.1
DNS=1.1.1.1
DNS=8.8.8.8
ConfigureWithoutCarrier=yes
EOF
```

> ✅ `ConfigureWithoutCarrier=yes` evita que la interfaz quede muerta si el cable se detecta tarde (problema típico en reinicios fríos).
> 

### Crea el shim macvlan del host (interfaz virtual)

```bash
cat > /etc/systemd/network/20-macvlan-shim.netdev <<EOF
[NetDev]
Name=macvlan-shim
Kind=macvlan

[MACVLAN]
Mode=bridge
EOF

cat > /etc/systemd/network/20-macvlan-shim.network <<EOF
[Match]
Name=macvlan-shim

[Network]
Address=192.168.0.250/32

[Route]
Destination=192.168.0.201/32
EOF
```

### Vincula el shim a la interfaz física (añade `MACVLAN=macvlan-shim`)

Edita el primer archivo y añade la línea `MACVLAN`:

```bash
cat >> /etc/systemd/network/10-${IFACE}.network <<EOF
MACVLAN=macvlan-shim
EOF
```

(verifica que quede dentro de la sección `[Network]`)

### 2.4 Activa systemd-networkd **sin apagar networking todavía**

```bash
systemctl enable systemd-networkd
systemctl start systemd-networkd
```

Ahora conviven `ifupdown` (DHCP) y `systemd-networkd` (IP fija).

### 2.5 Verifica que ambos coexisten

```bash
ip addr show ${IFACE}
# Debe mostrar: la IP vieja por DHCP (ej 192.168.0.14) y la nueva fija 192.168.0.200
networkctl status ${IFACE}
```

### 2.6 Prueba la conectividad con la nueva IP

```bash
ping -c 3 192.168.0.1   # al router
ping -c 3 1.1.1.1       # a internet
```

Si falla, espera 5 minutos y la red volverá sola. Si funciona, continua.

### 2.7 Apaga el sistema antiguo (ifupdown)

```bash
systemctl disable --now networking
```

**Puede haber un microcorte de 1-2 segundos.** Reconéctate a la nueva IP fija:

```bash
ssh root@192.168.0.200
```

### 2.8 Verificación final (debe aparecer **solo** la IP fija)

```bash
ip addr show ${IFACE}
# Debe mostrar: inet 192.168.0.200/24 ... scope global
# No debe haber IPs secundarias dinámicas.
```

Si aún ves una IP `secondary dynamic` (residuo del DHCP), elimina el cliente:

```bash
pkill dhclient
systemctl stop dhcpcd 2>/dev/null
systemctl disable dhcpcd 2>/dev/null
```

### 2.9 Asegura que la configuración persiste tras reinicio

```bash
systemctl is-enabled systemd-networkd   # debe decir "enabled"
```

## 🐳 Parte 3 – Instalar Docker y Docker Compose

```bash
apt install -y ca-certificates curl gnupg lsb-release
curl -fsSL <https://download.docker.com/linux/debian/gpg> | gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] <https://download.docker.com/linux/debian> $(lsb_release -cs) stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

Verifica:

```bash
docker run hello-world   # debe funcionar
```

## 🛡️ Parte 4 – Desplegar AdGuard con red macvlan

### 4.1 Estructura de directorios

```bash
mkdir -p /docker/adguard/{work,conf}
```

### 4.2 Archivo `compose.yaml`

```bash
cat > /docker/adguard/compose.yaml <<EOF
services:
  adguard:
    container_name: adguard
    image: adguard/adguardhome:latest
    cap_add:
      - NET_ADMIN
    networks:
      macvlan_NET:
        ipv4_address: 192.168.0.201
    volumes:
      - /docker/adguard/work:/opt/adguardhome/work
      - /docker/adguard/conf:/opt/adguardhome/conf
    restart: unless-stopped

networks:
  macvlan_NET:
    driver: macvlan
    driver_opts:
      parent: eno1
    ipam:
      config:
        - subnet: 192.168.0.0/24
          gateway: 192.168.0.1
EOF
```

> ⚠️ Cambia `parent: eno1` si tu interfaz se llama diferente.
> 

### 4.3 Levantar el contenedor

```bash
cd /docker/adguard
docker compose up -d
```

### 4.4 Verificaciones inmediatas

```bash
# ¿El contenedor está corriendo?
docker ps | grep adguard

# ¿El host puede hacer ping al contenedor? (gracias al shim)
ping -c 3 192.168.0.201

# ¿El servidor web de setup responde?
curl -I <http://192.168.0.201:3000>
```

### 4.5 Configuración inicial de AdGuard desde tu PC

Abre un navegador y ve a `http://192.168.0.201:3000`. Sigue el asistente:

- Puerto web admin: `80` (o mantenlo `3000` si quieres)
- Puerto DNS: `53`
- Usa el puerto `80` si quieres acceder sin puerto (pero ojo porque luego el panel de admin puede quedar en `:80`). Recomendación: en el asistente, configura el **panel de administración** en `8080` y el **DNS** en `53`.

Si eliges el puerto `80` para el panel, luego accederás con `http://192.168.0.201`. Si dejas `3000`, usa `http://192.168.0.201:3000`.

## 🔁 Parte 5 – Hacer que el resto de la red use AdGuard

**Desde el router** (si permite cambiar DNS):

- DNS primario: `192.168.0.201`
- DNS secundario: `1.1.1.1` (por si AdGuard falla)

O bien, configura manualmente cada dispositivo.

Para probar desde el servidor mismo:

```bash
echo "nameserver 192.168.0.201" > /etc/resolv.conf
ping google.com   # debe resolver
```

> En un sistema con `systemd-resolved` (aunque Debian no lo usa por defecto) haría falta `resolvectl dns`. Pero con `systemd-networkd` puro, editar `/etc/resolv.conf` es suficiente.

## 🧹 Limpieza de residuos (opcional)

Si quieres eliminar el antiguo sistema de red `ifupdown` por completo:

```bash
apt purge --auto-remove ifupdown isc-dhcp-client
rm -f /etc/network/interfaces
```

Pero **solo hazlo** si `systemd-networkd` lleva días funcionando sin problemas.

## 🆘 ¿Cómo recuperarse si la red falla?

1. Accede físicamente al servidor o por consola IPMI/iLO.
2. Ejecuta:
    
    ```bash
    systemctl stop systemd-networkd
    systemctl disable systemd-networkd
    systemctl enable --now networking
    dhclient eno1   # o `ip addr add 192.168.0.200/24 dev eno1` con ruta manual
    ```
    
3. Una vez recuperado, revisa los logs: `journalctl -u systemd-networkd`

## 🎯 Conclusión

Siguiendo **exactamente** este orden y con las verificaciones intermedias, evitarás el problema de "pierdo la red al reiniciar". La doble comprobación (`ConfigureWithoutCarrier=yes` + shim macvlan) garantiza que el host y el contenedor se vean entre sí y que incluso en arranques en frío la IP fija se asigne correctamente.

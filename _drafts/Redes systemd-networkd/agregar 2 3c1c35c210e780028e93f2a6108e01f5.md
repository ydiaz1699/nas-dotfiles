## Entonces el problema es otro

`systemd-networkd` **ya estaba habilitado** y aun así no levantaba la red al arrancar. Eso apunta a un problema de **orden de arranque** (race condition).

La causa más común en Debian: `systemd-networkd` levanta la interfaz pero el archivo `.network` no se procesa a tiempo, o `eno1` no tiene carrier todavía cuando networkd intenta configurarla.

### Solución: activar `systemd-networkd-wait-online`

```bash
systemctl enable systemd-networkd-wait-online
```

Esto hace que el sistema espere a tener red antes de continuar el boot.

---

### También verifica que el archivo .network tiene la opción correcta

```bash
cat /etc/systemd/network/10-eno1.network
```

Agrega esta línea bajo `[Network]` si no está: `ConfigureWithoutCarrier=yes`

```bash
[Match]
Name=eno1

[Network]
Address=192.168.0.200/24
Gateway=192.168.0.1
DNS=1.1.1.1
DNS=8.8.8.8
MACVLAN=macvlan-shim
ConfigureWithoutCarrier=yes
```

`ConfigureWithoutCarrier=yes` hace que networkd aplique la config **aunque el cable tarde un momento en detectarse**, que es exactamente lo que parece estar pasando.

---

Sí, puedes reescribir el archivo completo con un solo comando:

```bash
tee /etc/systemd/network/10-eno1.network << 'EOF'
[Match]
Name=eno1

[Network]
Address=192.168.0.200/24
Gateway=192.168.0.1
DNS=1.1.1.1
DNS=8.8.8.8
MACVLAN=macvlan-shim
ConfigureWithoutCarrier=yes
EOF
```

Verifica que quedó bien:

```bash
cat /etc/systemd/network/10-eno1.network
```

Y luego aplica:

```bash
systemctl restart systemd-networkd && reboot
```

Y prueba desconectando/reconectando la alimentación nuevamente.
